# Sculwave Security Policy

Sculwave welcomes responsible security research and reports that help protect its users and self-hosted deployments.

## Reporting a vulnerability

**Security contact:** [REPLACE WITH A MONITORED SECURITY EMAIL OR PRIVATE REPORTING LINK]

Please report suspected security vulnerabilities privately. Do not publish credentials, sensitive personal data, or detailed exploit instructions in public issues.

Include as much of the following information as you can safely provide:

- The affected component, version, release, or commit.
- A description of the vulnerability.
- The potential security impact.
- Reproduction steps or a proof of concept, where safe.
- Relevant logs or screenshots with secrets and personal information removed.
- Suggested mitigations, if known.

Please do not include real user data, passwords, API keys, access tokens, or private keys in your report.

## Scope

Reports may concern security issues in Sculwave components, including:

- Minecraft integration and client applications.
- The application server and self-hosted deployment.
- Authentication, authorization, and session management.
- Voice signaling, WebRTC configuration, and network access controls.
- File uploads, media storage, and API endpoints.
- Secret handling, dependency vulnerabilities, and deployment configuration.

Reports involving third-party services or dependencies should explain how the issue affects Sculwave, where possible.

## Responsible testing

Please:

- Test only systems you own or have explicit permission to assess.
- Avoid disrupting services or accessing, modifying, or exposing other people's data.
- Avoid denial-of-service testing and destructive actions against production systems.
- Give maintainers a reasonable opportunity to investigate and address a confirmed issue before public disclosure.

Do not test against other people's live Sculwave deployments without authorization.

## Response and disclosure

Maintainers will make reasonable efforts to review incoming reports, assess their impact, and coordinate remediation and disclosure.

Response times, fixes, and public advisories are not guaranteed. Please include a way to contact you if clarification is needed.

Once a vulnerability has been addressed, coordinated public disclosure may help users understand the issue and apply available fixes.

## Supported versions

Sculwave is currently in beta. Security fixes and support availability may vary by component and release. Unless a release-specific support policy is published, do not assume that every historical version receives security updates.

## Security audit status

Making source code available allows independent inspection, but does not establish that Sculwave has undergone a professional security audit or is free of vulnerabilities.

Please report suspected vulnerabilities using the private contact method listed above.
