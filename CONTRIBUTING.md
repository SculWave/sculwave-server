# Contributing to Sculwave

Thank you for your interest in contributing to Sculwave. Contributions help improve reliability, usability, documentation, and security for Minecraft communities.

## Ways to contribute

You can help by:

- Reporting reproducible bugs.
- Improving documentation and setup instructions.
- Reviewing code and suggesting improvements.
- Adding or improving tests.
- Fixing bugs and implementing features.
- Improving deployment, configuration, and security practices.

## Before opening an issue

1. Search existing issues to avoid duplicates.
2. Confirm the problem against the version or commit you are using.
3. Include relevant logs, error messages, configuration details, and reproduction steps.
4. Remove passwords, API keys, access tokens, private addresses, and personal information from anything you share.

For security vulnerabilities, follow [SECURITY.md](SECURITY.md) instead of opening a public issue.

## Pull request process

1. Fork the repository and create a branch for your changes.
2. Keep changes focused on one problem or feature where practical.
3. Explain the reason for the change and its expected behavior.
4. Add or update tests where appropriate.
5. Update documentation when configuration, installation, protocols, or behavior changes.
6. Check that you have not committed credentials, generated secrets, or unrelated files.
7. Submit a pull request with a clear description and testing notes.

Contributors may be asked to revise changes before they are accepted.

## Code quality and security

- Prefer clear, maintainable code over unnecessary complexity.
- Validate untrusted input at appropriate boundaries.
- Avoid logging credentials, authentication tokens, or sensitive user data.
- Do not introduce undocumented external dependencies or unexpected data collection.
- Do not weaken authentication, authorization, transport security, or upload validation to work around a bug.
- Explain security-sensitive changes in the pull request.
